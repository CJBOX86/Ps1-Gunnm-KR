# 타이틀 폰트 VRAM 가시성 PoC (2026-10-06)

## 방법
- emucap 1.0.0 + Mednafen 1.32.1 (psx), BIOS scph5500, 원본 redump 이미지 그대로 실행
- 약 2,970 프레임 진행 후 타이틀 화면 ("スタートボタンを押してください")에서 정지, 상태 저장 `work/title.mcs`
- `debug.dump_memory`로 VRAM(gpu 1MiB) 덤프 → `work/dump_title/gpu.bin`
- `work/cmp_vram.py`: 각 `TIM/K*.TIM` 이미지·CLUT을 VRAM과 바이트 비교
- `work/hangul_poc.py`: K00 글리프 셀 7개 비트플레인을 손으로 그린 한글로 덮어써 VRAM에 기록

## 결과
- 타이틀에서 적재된 폰트는 **K00.TIM** — 이미지 (960,0) 64x208 일치율 1.000, CLUT (960,248) 1.000. 다른 K*.TIM은 0.14~0.29
- 글리프 배치 확인: KNJ 인덱스 i → 비트플레인 i%4, 셀 i//4, 행당 19셀, 13x13 px (VRAM 디코드로 押·ス 정상 확인)
- 押→누, し→르, て→세, く→요, だ/さ/い→공백 으로 VRAM만 교체 → 화면에 "スタートボタンを**누르세요**" 표시 (`work/title_hangul_poc.png`, 확대 `work/title_hangul_zoom.png`)
- 정정: 첫 시도에서 누 비트맵에 윗 가로획을 넣어 화면에 "두"로 나왔음(사용자 확인). ㄴ으로 고친 뒤 재기록해 "누르세요" 확인. 화면 판정은 확대 캡처로 할 것
- 즉 문자열 코드 변경 없이 글리프 비트맵 교체만으로 한글이 렌더링됨. 렌더러는 VRAM 폰트 페이지를 매 프레임 참조함

## 의미·남은 질문
- 장별 폰트 교체(KNJ 코드 목록 + TIM 비트플레인) 방식으로 한글 공급 가능성 확인
- 용량: K00 = 208행/13 = 16행 × 19셀 × 4플레인 = 최대 1,216 글리프. 장별 필요 한글 음절 수가 이 안에 드는지가 Q2의 핵심
- 13px 셀 중 실제 표시 영역(세로 축소 여부)과 가독성 기준은 아직 미검증
