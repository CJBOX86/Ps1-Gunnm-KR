# 반각 띄어쓰기 — 2026-10-06

## 결론
한국어 띄어쓰기를 전용 코드 `81AD`(SJIS 미할당, 원본 대사 미사용)로 넣고, 대사 렌더러가 이 코드를 만나면 그리지 않고 창 글자 간격의 절반만 전진하도록 실행 파일을 고쳤다. 띄어쓰기 폭이 절반이 됨을 화면으로 확인 (`work/half_compare.png`).

## 대사 렌더러 (0x8005E8EC 루프, 실행 추적)
- 글자마다 `0x8005EF10`에서 현재 코드(halfword)를 읽고, 원래는 전각 공백 `8140`이면 그리기를 건너뛰고 `0x8005F020`으로 간다
- `0x8005F020`: x(+0x48) += 창 글자 간격(+0x0F 바이트), 칸 수(+0x4C) += 1, 칸 수가 최대(+0x44)에 닿으면 자동 줄바꿈
- 그리는 글자는 `0x800279F4`(코드 → 글리프 위치, 내부에서 KNJ 이진 탐색)로 UV를 얻는다
- 자동 줄바꿈은 픽셀이 아니라 **글자 수** 기준

## 수정 ([config/patches/halfwidth-space.json](../../config/patches/halfwidth-space.json))
- `0x8005EF14`: 비교 코드 `8140` → `81AD`
- `0x8005EF18`: 같으면 `0x8005EF9C` 스텁으로
- `0x8005EF94`: 나눗셈 오류 검사(`break`)를 건너뛰는 무조건 분기. 분모는 바로 앞에서 `|1`을 하므로 0이 될 수 없고, -1/0x80000000 검사는 트랩만 낸다
- `0x8005EF9C~`: `lbu a0,0xF(s0)` / `lhu v1,0x48(s0)` / `j 0x8005F028` / `srl a0,a0,1` — 절반 간격으로 원래 전진 처리에 합류
- 빌드는 모든 단어의 원래 값을 확인한 뒤 함께 적용한다
- 검증: 독립 인코더로 단어 값 대조, 실행 중 메모리 재디스어셈블이 설계와 일치

## 영향
- 일본어 원문의 전각 공백은 이제 빈 글리프(모든 K 폰트의 0번, 비어 있음 확인)를 그린다 → 화면 동일
- 반각 공백도 칸 수 1칸으로 센다 → 창 밖으로 넘치지 않고, 빌드의 25칸 검사도 그대로 맞다 (대신 공백이 많은 줄은 오른쪽이 조금 빈다)
- 이 코드는 대사 렌더러에만 해당. 메뉴 등 다른 렌더러에는 번역문 공백이 들어가지 않는다 (아직 메뉴 미번역)
- 기계어 검증은 템플릿의 Rust ISA 도구 대신 Python 인코더 대조 + 에뮬레이터 재디스어셈블로 했다 (`cargo` 없음)
