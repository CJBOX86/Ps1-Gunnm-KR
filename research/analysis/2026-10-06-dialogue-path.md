# 본편 대사 저장·소비 경로 (Q1) — 2026-10-06

## 결론
본편 대사는 맵 스크립트 파일(`M3`~`M6` 아래 `MP*.LDP` / `MP*.MP` / `*.EDP` 등) 안의 **대사 블록**에 SJIS를 **XOR 0x8C**로 암호화해 저장한다. 초기 조사의 평문 SJIS 검색에서 대사를 찾지 못한 이유다.

## 근거
- emucap 실행: 프롤로그 첫 대사 "男：ん？" 표시 중 RAM 0xB8A90 부근에 `WS2501b3男：brん？`(복호화됨, type 5) 다음 레코드들이 type 7 + 암호문으로 존재
- 같은 바이트열을 디스크에서 검색 → `/M3/O/MP801_0.LDP` 0x2E000 블록과 일치
- 쓰기 중단점: 복호화 루틴 `0x80034C3C` — halfword 단위 `xor 0x8C8C`, `0x0A0A` halfword에서 정지. 호출부 `0x80034978`는 복호화 후 플래그 bit1을 지우고(7→5), `0x8005DEB8(0x800F3350, record)` → `0x8005FE78`로 표시
- 디스크 반영 PoC에서 이 레코드를 바꾼 이미지가 실제로 바뀐 대사를 표시함 ([2026-10-06-disc-xdelta-poc](../poc/2026-10-06-disc-xdelta-poc.md))

## 블록 형식
```
u32 block_size      블록 전체 byte 수 (이 필드 포함)
u32 unknown         MP801: 0x28, MP106_2: 0xD4 — 의미 미확인
u16 n, u16 n
n × (u32 offset, u32 length)   offset은 블록 시작 기준, 첫 offset = 12+8n
record: u32 flags(디스크 7) + (SJIS ^ 0x8C) + 0A 0A, 4byte 정렬
```
- 종결 `0A0A`는 halfword 경계에 있어야 한다 (복호화가 2byte 단위). 본문 길이는 짝수로 맞춘다
- 대사 안의 ASCII 제어 코드: `WSxxxx`(창), `WP±xxx±xxx`(위치), `b2/b3/b5`(화자색?), `br`(화자명 뒤 줄바꿈), `\`(줄바꿈), `@@`(페이지), `[n`(선택지), `s3t0a1n1`, `BKCxxxFRCx`, `i010` 등 — 의미는 번역 도구 작업 때 확정

## 규모 (`tools/TEXT/dialog_scan.py` 결과, `work/dialog.jsonl`)
- 블록 769개, 레코드 19,226개, 고유 문장 13,399개 (제어 코드 포함 583k 문자)
- 같은 블록이 여러 파일에 중복 (예: `MP106_0`/`MP106_1`) — 재삽입 시 모든 사본을 함께 바꿔야 함
- 어떤 K 폰트로도 표시할 수 없는 글자 2개: `派`(M5/J/MP601_2.LDP), `縛`(M6/D/MP741_3.LDP) — 원본 결함 또는 미사용 대사

## 남은 질문
- 스캐너가 놓친 다른 형식의 블록이 있는지 (헤더 2번째 필드 의미 확인 필요)

- 메뉴·시스템 문자열(`NOR/*.E`, 실행 파일)과 `Y_MBDATA/MBTEXT.BIN` 등 다른 텍스트 경로
