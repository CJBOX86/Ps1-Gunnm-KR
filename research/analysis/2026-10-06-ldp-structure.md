# LDP 파일 내부 구조와 대사 길이 변경 재삽입 — 2026-10-06

## 결론
대사가 길어져도 재삽입할 수 있다. 대사 블록은 LDP의 마지막 섹션이라 늘려도 앞 섹션은 그대로이고, 게임은 파일을 ISO 디렉터리에서 이름으로 찾으므로 커진 파일을 디스크 끝으로 옮기고 디렉터리 레코드만 고치면 된다. 프롤로그 파일로 실제 확인함.

## LDP 헤더 (sector 0)
```
u32 1
u32 nsec
nsec × (u32 start_sector, u32 byte_size)   # 섹션은 2048 경계에서 시작
```
- 예: MP801_0.LDP = (1, 0x1FE64), (0x41, 0xD2A0), (0x5C, 0xB4). 파일 크기 = 마지막 섹션 끝을 2048로 올림
- 대사 블록은 **항상 마지막 섹션** (767개 전부)

## 대사 블록 (보강)
- 2번째 필드 = **최대 레코드 길이** (769개 블록 전부 일치). 스트리밍 슬롯 크기로 쓰인다
- 레코드 = `u32 7` + 암호문 + `0A0A` + `0000` + 4byte 정렬
- 레코드는 섹션 기준 2048byte 경계에 **닿거나 넘지 않게** 배치 (원본 위반 0건, 끝이 경계에 딱 맞는 경우도 다음 sector로 밀림)
- `tools/TEXT/ldp.py`의 `parse_block`/`build_block`으로 원본 767개 블록과 LDP 파일을 **byte 단위로 동일하게 재구성** 확인

## 게임의 대사 적재 방식 (실행 추적)
- 상태 구조체 0x8009101C, 상태값 +0x234
- 대사 섹션은 sector 단위로 **고정 버퍼 0x80091254 (2048byte)**에 CD에서 읽는다
- `0x80034E14`: 첫 sector를 창 버퍼(0x800B8A70~0x800BA26C, 6,140byte, 구조체 +8/+0xC)로 복사하고 오프셋을 포인터로 바꾼다. 들어가는 레코드 수만 상주시킨다
- `0x80034FEC`: 상주하지 않은 레코드는 `offset >> 11`로 sector 번호를 구해 그 sector 하나만 다시 읽는다 → 레코드가 sector 경계를 넘으면 안 되는 이유
- 파일 위치: 실행 파일이 `"%s.LDP;1"`로 경로를 만들고 ISO 디렉터리에서 찾는다 (`"dir was not found"` 메시지). 맵 기본 이름 표는 `NOR/WORLD00.E` (`\M3\O\MP801` 등)

## 디스크 여유 공간
- 대사 파일 뒤 빈 sector: 대부분 0개 (최대 5개). 원본 이미지 끝에 빈 Form 2 postgap 150 sector
- 따라서 커진 파일은 postgap 앞(LBA 225462~)으로 옮기고 postgap을 뒤에 다시 붙인다

## 실험 (`work/make_grow_inputs.py`, 이미지 `gunnm-kr-grow`)
- MP801_0.LDP 대사 블록 0xB4 → 2,112byte (2 sector), 파일 190,464 → 192,512byte
- 레코드 1을 보이지 않는 색 코드 `b3` 960개로 키워 레코드 2·3을 둘째 sector로 밀어냄
- `tools/DISC/build_disc.py`가 파일을 LBA 225462로 옮기고 디렉터리 sector 55706, PVD 볼륨 크기 갱신. 나머지 파일 LBA·내용 불변 검증, xdelta 왕복 일치 (136,801byte)
- emucap 실행 결과: 레코드 0 "남자：응？", 1 "남자：누르세요", 2 "남자：남자응？"(둘째 sector, 스트리밍), 3 원문 "男：ははははは" 모두 정상

## 남은 확인
- 창 버퍼 6,140byte가 장면마다 같은지, 최대 레코드 길이 상한
- 옮긴 파일 수가 많을 때 xdelta 크기 (옮긴 파일 전체가 패치에 들어감)
- `DATA/STS_0.SPB`, `M5/L/MP999_0.EDP`는 LDP가 아닌 컨테이너 — 별도 확인
